# Drop 0.10.0

Accounts have exactly one role: admin, developer or user. Admins manage accounts, catalog, nodes, placement and metering, and have no personal credits. Drop emails direct admin invitations. Customers keep one credit account when they switch between user and developer. Balances and usage show euro equivalents.

Developers create custom apps from a Linux executable, a tar.gz build or a download URL. Drop inspects its `--drop-manifest`, provisions the app by digest and serves it at the root of a generated `dev-…` hostname, where the app can require its own sign-in. Only the owning developer manages its deployment, release, settings and secrets, and custom release bytes stay encrypted at rest until the assigned node receives the key. Developers can submit an exact GitHub commit for catalog review. Admins publish official releases from reviewed commits, admin builds or public HTTPS URLs.

Every catalog release offers all eight compute tiers. Changing a tier resizes the app's disk only after the node confirms an offline resize, and refuses a downgrade that the guest's measured usage would not fit. Placement ranks eligible nodes by peak guest memory headroom, and the Nodes page shows 24 hourly memory peaks. Catalog and custom apps share the same dashboard cards, overview and resource settings. Official apps keep their lifecycle automatic across the reader, REST and MCP.

Owners of Crew releases that declare `platform_backup_v1` can buy optional backups: a scheduled daily copy, a ZIP download, and a restore to the original app or a new one. The Drop Agent's host services deliver guest sign-in codes, so the SMTP credential leaves the runner.

The reader uses app terminology throughout, guides you through connecting an MCP assistant in three steps, and fits phones with a floating page bar and a More sheet.

Back up the hosted project before upgrading. Nineteen schema migrations run on the first start. See the [upgrade instructions](../upgrades.md#from-090-to-0100).
