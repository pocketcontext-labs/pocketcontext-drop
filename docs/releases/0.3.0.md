# Drop 0.3.0

Drop meters each app's S3 use. The replica bucket's own server access logs and daily inventory, grouped by the `<app id>/` prefix that IAM already enforces on every guest session, become per-app hourly and daily usage. Each app has monthly limits: past a soft limit Drop records an event the owner and admins see, past a hard limit (ten times the soft one) it also stops the app once. The app page has a Usage tab with the last 24 hours, the month against the limits and an estimated cost; assistants read the same through `drop_read what=usage`.

- **Collector.** `drop serve` runs it every 15 minutes when `DROP_USAGE_LOG_BUCKET` and `DROP_USAGE_LOG_PREFIX` are set (`DROP_USAGE_INVENTORY_PREFIX` adds stored bytes); `drop usage collect` runs it once. Processed log objects are recorded with their counts in one transaction, so a crash or restart never counts twice. Only counts are stored: never a requester, address or request id. See [Hosting](../hosting.md#usage-metering).
- **Limits ("Standard").** Per app and calendar month (UTC): 100,000 Class A and DELETE requests, 1,000,000 Class B requests, 2 GB sent, 1 GB stored. Admins override an app's soft limits with `usage.set_limits` (`drop usage limits APP ...` or the Usage tab). Requests S3 denied (401, 403) never count against an app.
- **Request-metrics filters.** Crew apps get a CloudWatch request-metrics filter (`<app id>/`) on the replica bucket when created or restored, removed when archived; best effort, recorded as `app.metrics_filter` events and reconciled by every collector run.
- **Crew sync interval.** Crew apps take `replica_sync_interval` (1s-300s, default 10s for new Crew apps; `drop app set APP --replica-sync-interval 10s`), handed to the guest as `DROP_REPLICA_SYNC_INTERVAL`. A Crew guest that reads it is a separate Crew Drop release.
- **Operations.** New: `usage.get` (user), `usage.set_limits` and `usage.collect` (admins; neither through MCP). New events: `app.usage_exceeded`, `app.metrics_filter`, `usage.set_limits`, `usage.collect`.
- **Schema.** Migration `1820001700_usage.js`: collections `app_usage_hourly` and `app_usage_daily`, the apps fields `usage_limits` and `replica_sync_seconds`, three private tables. The desired document gains `replicaSyncSeconds` on Crew apps that set it.
