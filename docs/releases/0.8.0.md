# Drop 0.8.0

Open a catalog entry or a shared `/deploy` link to review a release before deploying it. The link can carry the upstream HTTPS URL, SHA-256, HTTP port and exact launch arguments. PocketBase and ZeroClaw have pinned catalog entries. Manual deployments can also upload release files.

Drop imports ZIP and tar.gz archives, checks the supplied checksum, and lets the owner choose the executable when an archive has multiple candidates. The deployment includes the selected assets. The status page checks the assigned HTTPS address and provides the owner with the applicable first-run action.

The login screen asks for an email first. After submission, admitted users can request a code and other visitors can consent to joining the waitlist. This flow discloses whether an address is admitted before verifying control of the mailbox.

Permanent deletion shows the affected resources and requires the exact app slug. Owners can track the cleanup receipt after leaving the page, including when a node or the cleanup worker must retry.

Back up the hosted project before upgrading. See the [upgrade instructions](../upgrades.md#from-070-to-080).
