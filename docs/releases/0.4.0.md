# Drop 0.4.0

Drop can keep AWS credentials out of managed Crew guests. With host services on, a node's S3 proxy (`drop agent host-services`) serves each Crew guest's S3 traffic. NibRunner relays it from the guest's loopback endpoint over vsock 51007. The proxy signs again with the app's own STS session, confines requests to the app's `<app id>/` prefix and Crew's operations, and enforces limits in real time. Guests hold only placeholder keys, so a copied key is worthless.

- **Host services.** `drop agent host-services` is a separate process with its own unit (`deploy/drop-ax41/drop-agent-host-services.service`). It accepts only nibrunnerd (`SO_PEERCRED`) and serves a deployment only while both `desired.json` and the agent's `host-services.json` name it. It refuses version IDs, copies and anything outside the app's bucket and prefix. See [Node agent](../agent.md#host-services).
- **Real-time limits.** 20 requests per second with bursts of 200 (503 SlowDown), a 100 MiB object cap (including multipart uploads), and the app's stored-bytes quota and monthly download budget. The last two come from the app's hard limits in the desired document (`limits`).
- **Opt-in per node.** `DROP_AGENT_HOST_SERVICES=s3` gives managed Crew apps host S3 instead of a workload identity token. The agent removes their token files, and nibrunner skips identity delivery for them. Without the variable, apps keep workload identity as in 0.3.0.
- **Usage from the node.** Each agent report carries the proxy's counters for the app's deployment (`usage`). The server keeps a running total per node report (migration `1820001900_host_usage.js`), next to the Phase 1 figures from S3's own logs, which stay the trusted meter.
- **Requirements.** NibRunner with `hostServices` and the vsock 51007 forwarder (`[host_services] socket`), and a Crew for Drop guest that uses `AWS_ENDPOINT_URL_S3` (0.45.4-drop.3 or later).
