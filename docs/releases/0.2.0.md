# Drop 0.2.0

Hosted owners can enroll Crew using the app name and slug. Drop binds its verified sign-in recipient, private lifecycle listener, replica storage and per-app AWS identity. The app Overview shows the last hook event, outcome and time. Ordinary apps can opt into lifecycle hooks through the Hooks port setting or `drop app set APP --hook-port PORT`.

## Upgrade from 0.1.0

1. Back up the Drop project and retain the current server, agent and NibRunner binaries. Rollback of a migrated control database requires the pre-upgrade backup. Follow the hosted restore procedure when restoring a copy.
2. Install the NibRunner release with `config.hooks.port` support and the host SMTP credential. Configure the issuer, shared role, replica bucket and node signer according to [Hosting](../hosting.md). Set `DROP_CREW_REPLICA_BUCKET`, `DROP_AWS_REGION` and `DROP_APP_DOMAIN` on the server.
3. Upgrade the server and agents before enabling hooks or creating a managed Crew app. Existing apps keep their listener settings, executable, environment and volume. Pre-upgrade Crew apps retain their existing sign-in delivery and operator-managed runtime configuration.
4. After a new enrollment, verify the owner can sign in, write data and replicate to its S3 prefix. Run `drop app set APP --finish-enrollment` as the owner to remove initial empty-namespace creation permission. Recheck sign-in and access to the same data after the deployment restarts.
