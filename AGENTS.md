# Drop

PocketContext Drop: a private, invite-only service that runs people's apps (one Linux executable each) on PocketContext-managed hosts, built as one Go binary. Derived from the PocketContext template (`docs/origin.md`), it serves people in hosted multi-account mode on `github.com/pocketcontext-labs/pocketcontext-core`, pinned to an exact tag in `go.mod`. This repository holds identity, policy, route allowlist and copy (`internal/droppolicy`), the operations' wire contract (`internal/dropapi`), hooks, accounts and the operation framework (`internal/dropserver`), the runtime wiring (`internal/appconfig`), the CLI, the data model and the reader. Accounts have roles and come only from invites; apps (`apps`, with their settings, quota and deployment number) and the names of their secrets (`app_secret_names`; values only in SSM) are written by the `app.*` and `secret.*` operations; releases (`releases`, bytes only in S3 at `releases/<sha256>`) by the one-time upload route and the `release.*` operations; nodes (`nodes`, an auth collection of its own), placements and node reports by the `node.*` and `placement.*` operations and the agent routes (`docs/agent-api.md`); the node agent (`drop agent`, `internal/agent`, manual docs/agent.md) writes nibrunner's `desired.json` on each host. The app value rules live in `internal/appspec`, shared by the server's operations and the node's renderer (`internal/render`): change them there, never in one side only. Read docs/ops.md before adding or changing an operation. Read README.md, docs/data-model.md and docs/hosting.md before changes.

- Keep the project to the database file, `storage/`, `drop.json` and the binary. Everything machine-specific (working copy, logs, local key, unpacked assets, tokens, OAuth state) belongs in the per-machine cache. Never write PocketBase runtime files (`.notify`, `auxiliary.db`, `types.d.ts`, backups) into the project folder.
- Never let the server open the synced database directly. Copy it in on start and write back only through consistent snapshots (`VACUUM INTO`) and atomic renames. Never overwrite a synced file that changed elsewhere; keep both and require an explicit `recover`. A database whose applied migrations this release does not ship is refused before PocketBase opens it (core's `CheckDatabase`, tested in `internal/appconfig/schema_test.go`); never edit or rename a migration that has shipped.
- Do not add dependencies on external tools, Python or network services at run time beyond the hosted SMTP server that core uses for sign-in email. Hooks and migrations run in-process: no `$os.cmd`/`$os.exec` or other `$os` calls (`internal/appconfig/hooks_test.go` enforces it; `sha256sum` and similar tools do not exist on every platform). There is no tunnel: do not add one back.
- Keep authentication on: Host check, own-origin CORS, ordinary `users` tokens on every API, including SQL and search. People use Drop only in hosted mode (`serve --hosted --headless --domain HOST --mcp`, `docs/hosting.md`): several accounts (`Policy.Accounts` = `AccountsMulti`), email sign-in, remote MCP with OAuth, plain HTTP behind a TLS-terminating proxy. The proxy options (`--hosted-http-address`, `--hosted-proxy-header`, `--hosted-proxy-networks`) live only in `internal/client/serve_hosted.go`; never trust a client-address header without an explicit `--hosted-proxy-networks`. Plain `serve` is the local single-account server on loopback, for developing the reader; there is no native public HTTPS mode. Never enable hosted mode by default or from project configuration.
- The hosted origin is default-deny: `internal/droppolicy/routes.go` `PublicRoute` is the whole allowlist, and `internal/droppolicy/testdata/public_routes.json` is its golden table (`routes_test.go`). The table is frozen: a change to it is a reviewed diff (`-update-routes`) plus a hand edit of the allowed rows in `frozenAllowed` (`TestPublicRouteTableFrozen`), which needs the owner's review and is never widened to make a test pass. The node agent's routes (nodes sign-in and refresh, `GET /api/drop/agent/desired`, `POST /api/drop/agent/report`) are on it for node tokens only: a node token reaches nothing but those routes, its own `nodes` record and its own placements (`TestNodeIsolation`), every rule that admits a node checks `@request.auth.collectionName = 'nodes'`, and a node's desired document never carries a secret value. Every change that alters a node's desired document bumps its `desired_seq` in the same transaction (`seq.go`), and reports write to the database only on change or every five minutes (`heartbeat.go`). The one anonymous write is `PUT /api/drop/upload/<token>` (a one-time release upload, scoped to one link by its 32-character token, `internal/dropserver/upload.go`); never widen its token pattern or add another anonymous write, and keep its token out of logs (the route logs `[redacted]`). Record writes, `users` records, `/api/batch`, `/api/files/*`, the SQL and search reads (`/api/context/*`, which read whole tables and stay with the owner's local key) and every local administration route stay off it. The anonymous loopback route table `tests/testdata/public_routes.json` (`tests/public_routes.py`) is frozen; never widen it.
- Accounts: core creates the owner (`DROP_OWNER_EMAIL`, on `--hosted-init`) and any other account only when `Hooks.AllowSignIn` admits the address (`internal/dropserver/accounts.go`): Drop is invite-only, so only an address with an open, unexpired invite; never add open sign-up. Every account has a `role` (`admin`, `developer` or `user`, one OAuth scope `drop`, no `drop:admin`); the owner and the local account are admins, an invited account takes its invite's role, and the users create hook refuses any other account. Invites return a sign-in URL; Drop emails direct admin invitations and waitlist approvals. Admin role changes require a separate invited identity. Nobody changes their own role or suspension, or the owner's. Suspend accounts; never delete one that signed in. `pb_hooks/account_access.js` accepts several accounts and lets core prune accounts that never signed in, but refuses to delete one that has. Every record belongs to an account: collection rules filter by owner (`owner = @request.auth.id`; admins may also read invites and events) and Go code sets the owner from the request, so one account never reads or changes another's records; `Runtime.IsOwner` tells the owner apart, and core authorizes nothing between accounts. Hosted accounts all share one name: the reader shows email addresses. Never open a rule to anonymous requests, and guard every rule that reads an account field (`role`, `suspended`) with `@request.auth.collectionName = 'users'`.
- Drop is hosted multi-user: every feature is designed for several accounts on one instance from the start, never for one account first. Each party reads only its own data: an account its apps and their releases, secret names, reports and events; a developer can deploy private Linux executables and submit an exact GitHub commit for catalog review; a hosted admin administers accounts, catalog, nodes, placement and metering; a node only its own record, placements and desired document. The isolation suite holds this (`internal/dropserver/isolation_test.go`, whose header is the matrix: users A and B, admin O, nodes N1 and N2 across the records API, operations, upload, agent routes, realtime, MCP and the browser). A new collection, field, route, operation, `what` value or realtime topic adds its rows to that matrix in the same change. Credentials and secret values are checked with the leak scan (`internal/leakscan` in Go tests, `tests/leak_scan.py` in the end-to-end tests) over databases, logs, events, node reports, answers, MCP output and the agent's files; add every new place a credential could land to a scan. `--hosted-restore` invalidates every credential a copied backup carries: core rotates the accounts', Drop invalidates unused upload links and rotates the nodes' token keys (`Hooks.OnHostedRestore`, `restore.go`). Placement checks a node's total: the apps placed on it, archived ones aside, must fit its allocatable together (`checkNodeRoom`).
- The node agent runs as root on a host shared by many accounts, so its validation is the security boundary: it treats the server's desired document as untrusted input and validates every field before anything reaches `desired.json` (plan 7.3, `internal/appspec` and `internal/render`: app, deployment and volume ids, sha256 and `releases/<sha256>` keys, executable names, SSM parameter paths under its own prefix and app, hostnames under its allowed suffix, env names and values, resources within its own allocatable, idle timeouts, desired states). The server never chooses a path, command, parameter outside the app's prefix or host suffix; a bad app is rejected alone, a malformed document whole, and the agent writes nothing on any doubt. Never relax a check on the agent's side because the server already checked it; the server's own check (`rejected`) is a convenience, not the boundary.
- Only the owner’s or admin’s explicit `app.delete` with the immutable app ID and exact typed slug authorizes permanent removal of that app’s volumes, replica versions, releases and SSM secrets. Archive, unplace, moves and missing desired entries retain the volume. Keep shared release bytes, events, ledger entries and accounts. Node teardown requires an explicit server deletion marker and a matching canonical local volume.
- Writes go through operations: `POST /api/drop/op` (`internal/dropserver/ops.go`, contract in `internal/dropapi`, manual `docs/ops.md`) handles account operations from the reader, CLI and MCP. Uploads and agent reports have their own write routes. Each operation is registered in `dropapi.Specs` with its role and input type and in a dropserver handler (`TestEveryOperationHasAHandler`, and `ui/src/dropApi.ts` `OPS` must list the same names); it decodes its input with unknown fields refused, runs in one transaction and writes exactly one `events` row, whose detail never holds a secret value. Return the framework's errors (`Invalid`, `NotFound`, `Forbidden`, `Conflict`); another account's record is a 404, never a 403. New collections close every write rule. Secret values never reach the database, an event, an answer, an error or a log line: the server holds the secret store only as an `awsx.SecretWriter` (`dropserver.Services`, handed over by serve), `secret.set` ignores idempotency keys (`Spec.SecretInput`), and `TestSecretSentinel` and `TestServerNeverReadsSecrets` keep it so. Idempotency keys replay results for 24 hours; an operation whose result is shown only once sets `OnceResult` so it is never stored.
- MCP tools: Drop has exactly two, `drop_read` and `drop_write` (`internal/client/drop_mcp.go`, manual `docs/mcp.md`), served by two MCP servers (user and admin, picked per request through `GET /api/drop/me`) with role-specific enums. Both call only `POST /api/drop/op` in-process with the caller's own account, so the server checks role and ownership on every call. `drop_write`'s op enum and table are generated from the specs with `MCP: true` (`TestMCPWriteTableMatchesRegistry`, `TestMCPWriteOpsFollowTicket`); `drop_read`'s `what` values map to read operations in the one table `dropReads`. New features add operations or `what` values, never tools: a new tool needs the owner's approval, and never add shell, filesystem or administration tools. Tools decode their own arguments and never echo one; results keep only a secret's name, length, updated and set_via; diagnostics stay metadata-only (`droppolicy.Observe`); `TestMCPSecretSentinel` keeps it so. The local key never leaves the private cache.
- Remote mode (`--url`) is a client only: it never resolves or creates a database, never starts a server and never reads the local key. It accepts loopback URLs only and stores a token, never a password.
- The SQL reader reads the live database and exposes only the columns listed in `server.json` `tables`, never auth collections, credentials or SQLite metadata. `build-tags.txt` is copied unchanged from pocketcontext-core and enables exactly the SQLite features tested in `internal/appconfig/sqlite_test.go` (its tailscale tags are unused here); do not add icu, userauth, allow_uri_authority, secure_delete, vacuum, foreign_keys, app_armor or os_trace, and keep the reader's denial of `dbstat`, `pragma_*`, `sqlite_schema`, FTS shadow tables and writes.
- Keep the vendored server in `internal/pocketcontext/` under its upstream name (its `database`, `sqliteuri` and maintenance packages live in pocketcontext-core). Review security fixes in PocketContext (see `docs/origin.md`), the vendored server (`internal/pocketcontext/VENDORED.md`) and pocketcontext-core and port them by hand. Never add a `replace` directive for pocketcontext-core; a core fix ships as a tagged core release and a pin bump here.
- Never introduce the retired product name that `tests/name_check.py` checks for: not in files, file names, messages, tests or the binary.
- Drop is Linux only (amd64 and arm64): CI runs on `ubuntu-24.04` and `ubuntu-24.04-arm`, releases build `linux_amd64` and `linux_arm64`, and `cmd/drop/main_other.go` (`//go:build !linux`) makes every other system's build refuse to run. Do not add macOS or Windows code, installers, CI jobs or release platforms. A future laptop client would be a separate pure-Go program (no cgo) calling Drop's API, not this binary. pocketcontext-core stays cross-platform for its other applications; the vendored `internal/pocketcontext/` keeps its upstream platform files.
- Tests use synthetic data in temporary folders. After changes run `make test` (Go tests with the tags in `build-tags.txt`, including the hosted tests built on `internal/droptest`, the launcher test and the Python unit tests `tests/test_*.py`), `python3 tests/name_check.py --binary bin/drop`, `python3 tests/identity_check.py --binary bin/drop`, `python3 tests/public_routes.py --binary bin/drop`, `python3 tests/e2e.py --binary bin/drop` and `python3 tests/drop_e2e.py --binary bin/drop` (`make e2e` runs all five); rebuild `ui/dist` first when the reader changes.
- The node agent (`internal/agent`, `drop agent run|check|render`, docs/agent.md) is the only writer of nibrunner's `desired.json` and runs as root, so its validation is a security boundary. Drop owns the whole file: the agent refuses to start and `check` fails (exit 3) when it holds any entry whose appId does not start with `d-`, naming them, and it never deletes what it did not create. It never writes `desired.json` when the server is unreachable or answers an error, writes it only atomically (fsync, rename, fsync the directory) after copying the current file to `desired.json.drop-prev`, never references an unstaged artifact and emits `absent` only for the confirmed deletion above. Secret values and tokens stay in memory and in `desired.json`: never in `state.json` (`/var/lib/drop-agent/state.json`), a report, a log or an error, and reports never carry nibrunner's `cron`. `drop agent` is dispatched before any project is resolved and takes no `--db` or `--url`. Tests and local runs use temporary paths and `--fake-aws`; never point them at `/var/lib/nibrunner`.
- Never commit `bin/`, `ui/dist`, databases, secrets, real data or machine-specific paths. The repository is private, but treat every commit as if it could be published.

## Identity

- `tests/identity_check.py` (`make identity`, CI and release) must keep passing: none of the template's name, repository, hello-world collection or default port (assembled from parts in that file) in file names, contents or the binary outside its allowlist (`docs/origin.md`), and no identity field in `internal/droppolicy/policy.go` at the template's value. Do not change its needles or logic; an `ALLOWED` entry needs a reason a reviewer can verify. The identity values (`drop`, `pocketcontext-drop`, port 8100, `account@drop.invalid`, OAuth scope `drop`) are persisted: never change one after the first release.
- Keep every change passing `make ui build test names identity e2e`, the reader, development and two-tenant browser checks (in CI) and the docs and skill accurate to the code.
