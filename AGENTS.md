# Drop

PocketContext Drop: a private, invite-only service that runs people's apps (one Linux executable each) on PocketContext-managed hosts, built as one Go binary. This first scaffold, derived from the PocketContext template (`docs/origin.md`), still has the template's single-account local model with a placeholder collection, `apps` (name, unique slug); later milestones replace it with the hosted multi-account service. The server is the shared library `github.com/pocketcontext-labs/pocketcontext-core`, pinned to an exact tag in `go.mod`; this repository holds identity, policy and hooks (`internal/appconfig`), the CLI, the apps model and the reader. Read README.md and docs/data-model.md before changes.

- Keep the project to the database file, `storage/`, `drop.json` and the binary. Everything machine-specific (working copy, logs, local key, unpacked assets, tokens, tunnel identity) belongs in the per-machine cache. Never write PocketBase runtime files (`.notify`, `auxiliary.db`, `types.d.ts`, backups) into the project folder.
- Never let the server open the synced database directly. Copy it in on start and write back only through consistent snapshots (`VACUUM INTO`) and atomic renames. Never overwrite a synced file that changed elsewhere; keep both and require an explicit `recover`. A database whose applied migrations this release does not ship is refused before PocketBase opens it (core's `CheckDatabase`, tested in `internal/appconfig/schema_test.go`); never edit or rename a migration that has shipped.
- Do not add dependencies on external tools, Python or network services at run time. Hooks and migrations run in-process: no `$os.cmd`/`$os.exec` or other `$os` calls (`internal/appconfig/hooks_test.go` enforces it; `sha256sum` and similar tools do not exist on every platform).
  The one exception is the opt-in `tunnel` command (core's `tunnel` package), which uses the tailcat library and its relays: it admits only the project's port, proxies it to `127.0.0.1` only, keeps its identity in the per-machine cache and never logs or echoes the address. Do not widen it (other ports, forwarding through the server, UDP, exit nodes, shells or files), and keep `build-tags.txt` in step with the tailcat release in `go.mod`.
- Keep authentication on: Host check, own-origin CORS, ordinary `users` tokens on every API, including SQL and search. Listening is loopback only by default; a public listener exists only when explicitly requested with `serve --headless --domain HOST` (native HTTPS, see `docs/https.md`), and MCP only when `--mcp` is added to it (`docs/mcp.md`). Never enable either by default, from project configuration or without the user asking. The anonymous loopback route table `tests/testdata/public_routes.json` (`tests/public_routes.py`) is frozen; never widen it. The public origin fails closed: it exposes only the collections listed in `server.json` `public.collections`, an unlisted collection is denied, and auth or system collections in that list are refused at startup, as is any entry in `tables` that is not listed (SQL and search read every entry in `tables`). Public start also refuses an account password not saved with at least 12 characters, at least 5 of them different; the `publicPasswordStrong` flag records this when a password is saved. Local administration stays private. The MCP tools are exactly `read`, `search`, `schema`, `query` and `write`; never add shell, filesystem or administration tools. Hosted mode (`--hosted`, container deployment, email login) is out of scope here. The local key never leaves the private cache. A project is single-user: `users` holds exactly one hidden account, created by `init` (`pb_hooks/account_access.js` refuses a second one and any deletion); there is no account management, no record ownership and no per-requester read filtering. Collection rules require that account (`@request.auth.collectionName = 'users'`); never open a rule to anonymous requests.
- Remote mode (`--url`) is a client only: it never resolves or creates a database, never starts a server and never reads the local key. It accepts loopback URLs only and stores a token, never a password.
- The SQL reader reads the live database and exposes only the columns listed in `server.json` `tables`, never auth collections, credentials or SQLite metadata. `build-tags.txt` is copied unchanged from pocketcontext-core and enables exactly the SQLite features tested in `internal/appconfig/sqlite_test.go`; do not add icu, userauth, allow_uri_authority, secure_delete, vacuum, foreign_keys, app_armor or os_trace, and keep the reader's denial of `dbstat`, `pragma_*`, `sqlite_schema`, FTS shadow tables and writes.
- Keep the vendored server in `internal/pocketcontext/` under its upstream name (its `database`, `sqliteuri` and maintenance packages live in pocketcontext-core). Review security fixes in PocketContext (see `docs/origin.md`), the vendored server (`internal/pocketcontext/VENDORED.md`) and pocketcontext-core and port them by hand. Never add a `replace` directive for pocketcontext-core; a core fix ships as a tagged core release and a pin bump here.
- Never introduce the retired product name that `tests/name_check.py` checks for: not in files, file names, messages, tests or the binary.
- Drop is Linux only (amd64 and arm64): CI runs on `ubuntu-24.04` and `ubuntu-24.04-arm`, releases build `linux_amd64` and `linux_arm64`, and `cmd/drop/main_other.go` (`//go:build !linux`) makes every other system's build refuse to run. Do not add macOS or Windows code, installers, CI jobs or release platforms. A future laptop client would be a separate pure-Go program (no cgo) calling Drop's API, not this binary. pocketcontext-core stays cross-platform for its other applications; the vendored `internal/pocketcontext/` keeps its upstream platform files.
- Tests use synthetic data in temporary folders. After changes run `make test` (Go tests with the tags in `build-tags.txt`, the launcher test and the release tests), `python3 tests/name_check.py --binary bin/drop`, `python3 tests/identity_check.py --binary bin/drop`, `python3 tests/public_routes.py --binary bin/drop` and `python3 tests/e2e.py --binary bin/drop` (`make e2e` runs all four); rebuild `ui/dist` first when the reader changes.
- Never commit `bin/`, `ui/dist`, databases, secrets, real data or machine-specific paths. The repository is private, but treat every commit as if it could be published.

## Identity

- `tests/identity_check.py` (`make identity`, CI and release) must keep passing: none of the template's name, repository, hello-world collection or default port (assembled from parts in that file) in file names, contents or the binary outside its allowlist (`docs/origin.md`), and no identity field in `internal/appconfig/appconfig.go` at the template's value. Do not change its needles or logic; an `ALLOWED` entry needs a reason a reviewer can verify. The identity values (`drop`, `pocketcontext-drop`, port 8100, `account@drop.invalid`, OAuth scope `drop`) are persisted: never change one after the first release.
- Keep every change passing `make ui build test names identity e2e`, both browser tests (in CI) and the docs and skill accurate to the code.
